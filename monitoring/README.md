# S3Slower Monitoring Stack

Prometheus + Grafana monitoring for s3slower stress tests.

## Quick Start

```bash
# From the project root:
make monitoring-up       # Start Prometheus + Grafana
make monitoring-down     # Stop everything
make monitoring-logs     # Tail container logs
```

Or directly:

```bash
cd monitoring
podman-compose up -d     # or docker-compose up -d
```

## Access

- **Prometheus**: http://localhost:9090
- **Grafana**: http://localhost:3000 (admin/admin, anonymous viewer enabled)

## Prerequisites

- `podman-compose` or `docker-compose`
- s3slower running with `--prometheus --port 9000`

## Architecture

```
s3slower (:9000/metrics) --> Prometheus (:9090) --> Grafana (:3000)
```

All containers use `network_mode: host` to reach s3slower on localhost.

## Dashboard

`grafana/dashboards/s3slower.json` (generated by `make dashboard` from
`grafana/generate_dashboard.py`; edit the generator, not the JSON) is provisioned as **S3Slower - S3 Client
Latency Monitor** (`/d/s3slower-main`). Filters: host (`instance`), client,
operation, and the opt-in `bucket`/`endpoint` labels.

| Section | Shows |
|---------|-------|
| Overview | Requests/s, read and write throughput, GET p50/p99 (time to first byte), PUT/part p99, error rate, events dropped |
| Workload mix | Requests/s and requests in range by operation family; read and write throughput by family |
| Latency | Data-path p50/p99 and metadata p99 (log scale); latency heatmap |
| Per-operation detail | Table of every operation: requests, rate, average payload, throughput, p50, p99, errors |
| Clients | Requests/s, p99 and throughput per client |
| Errors & HTTP status | Responses by status class; 4xx/5xx by operation and code |
| Tracer health | Exporter up; dropped events by reason |

Charts group operations into eight families (GET, GET range, PUT, MPU part,
MPU control, LIST, HEAD, DELETE) with fixed colors; the table lists every
operation. Rates use `$__rate_interval`, so graphs react within ~20 s of a
workload starting.

## Recording Rules

Pre-computed metrics for dashboard performance:

| Rule | Description |
|------|-------------|
| `s3slower:request_rate_5m` | Request rate per label set |
| `s3slower:error_rate_5m` | Error rate per label set |
| `s3slower:throughput_bytes_5m` | Combined upload+download throughput |
| `s3slower:request_duration_p50` | 50th percentile latency |
| `s3slower:request_duration_p95` | 95th percentile latency |
| `s3slower:request_duration_p99` | 99th percentile latency |

## Alerts

| Alert | Condition | Severity |
|-------|-----------|----------|
| S3SlowerHighLatency | p95 > 1000ms for 5m | warning |
| S3SlowerHighErrorRate | errors > 0.1/sec for 2m | critical |
| S3SlowerExporterDown | target down for 1m | critical |
| S3SlowerVeryHighLatency | max > 5000ms for 1m | critical |

## Storage

- Prometheus retention: 120h (5 days), 10GB cap
- Data persisted in named volumes: `prometheus-data`, `grafana-data`

## Cleanup

```bash
make monitoring-down
podman volume rm monitoring_prometheus-data monitoring_grafana-data  # remove data
```
